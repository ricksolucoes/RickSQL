## Confirmed coverage limitations

Reviewing this matrix against the current source confirms that **all 43 units have an explicit coverage decision**, but this is not equivalent to 100% line or branch coverage. The 217/217 result proves the branch actually compiled/executed (`RICK_VCL_CONNECTION`, without `FULL_EDITION`). The current execution evidence does not cover:

- `FULL_EDITION` branches for DB2, Informix, SQL Server, ODBC, Oracle, and SQL Anywhere;
- `TFDODBCNativeError` SQLState extraction, also guarded by `FULL_EDITION`;
- `CONSOLE` and `RICK_FMX_CONNECTION` wait-provider selection in the client-library resolver;
- real Firebird/PostgreSQL or other external-server access when environment variables/infrastructure are absent;
- a line/branch coverage percentage, because no coverage-instrumentation report was supplied.

These limitations are not counted as implicit success; they remain conditional/environment-dependent.

## Criterion

Coverage is considered sufficient when each relevant responsibility has an explicit decision and a test level proportional to its risk. `INDIRECTLY AND SUFFICIENTLY COVERED` means a higher-level functional flow exercises the responsibility and an isolated test would not add a useful observable contract. `DOES NOT JUSTIFY AN ISOLATED TEST` does not mean unused: basic enums/types are exercised by the contracts that consume them.
